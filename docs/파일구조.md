# PhysiClinic 파일 구조

고등학교 물리 오개념 진단·교정 플랫폼. 이 문서는 **어떤 파일이 무엇을 맡는지**와
**무언가를 고치려면 어디를 열어야 하는지**를 정리한 지도다.

- 서비스 주소: https://physics-tuter.web.app
- 구성: Firebase (Hosting + Cloud Functions + Firestore + Auth) / AI는 Gemini 2.5 Flash
- 프레임워크 없음. 빌드 도구 없이 브라우저가 `<script>`로 바로 읽는 순수 JS다.

---

## 1. 전체 흐름

```
사진 촬영
   ↓  extractKeywords
단원·오개념 인식
   ↓  (소단원 첫 방문이면) 사전 진단검사
   ↓  generateQuestions
문제 출제  ─ Level 1·2A: 문장 5개 중 틀린 것 찾기
           ─ Level 2B  : 계산 단답형
           ─ Level 3   : 다단계 계산 + 손글씨/사진 풀이
   ↓  학생이 풀이
   ↓  gradeAnswers  (Level 3는 recognizeSolutionImage → gradeSolutionProcess)
채점 + 개념별 판정
   ↓  BKT
오개념별 이해도 P(L) 갱신
   ↓
숙달(P(L) ≥ 0.90)이면 다음 레벨로 승급
```

핵심은 **점수와 이해도가 분리되어 있다**는 점이다. 문항 점수는 관대하게 주되,
이해도는 학생이 서술에 실제로 쓴 만큼만 오른다.

## 3. 서버 — `functions/`

### 실제로 배포되는 것은 두 개뿐

| 파일 | 줄 | 맡은 것 |
|---|---|---|
| **`index.js`** | 1125 | AI 함수 5개 + 요청 검증 + 재시도 + 채점 집계 |
| **`prompts.js`** | 532 | **AI에게 보내는 글.** 전부 문자열만 만들어 돌려주는 순수 함수 |

**AI 함수 5개**

| 함수 | 하는 일 |
|---|---|
| `extractKeywords` | 사진 → 소단원 분류 + 오개념 후보 |
| `generateQuestions` | 문제 생성 (문장 5개 / 계산 단답 / Level 3) |
| `recognizeSolutionImage` | 손글씨·사진 → 텍스트 (OCR) |
| `gradeSolutionProcess` | Level 3 풀이 과정 채점 |
| `gradeAnswers` | 서술형 채점 + 오개념별 판정 |

모든 함수가 같은 순서를 지킨다.

```
requireAuth  →  요청 검증  →  countUsage(사용량 차감)  →  AI 호출
```

거절할 요청으로 하루 사용량을 깎지 않기 위해서다. 한도는 uid당 하루 **게스트 40회 /
로그인 400회**.

## 4. 자동 시험 — `functions/test/`

```bash
cd functions && npm test
```

네트워크를 쓰지 않고 요금도 들지 않는다. Gemini SDK와 Admin SDK를 가짜로 바꿔치기하고
실제 함수를 그대로 부른다.

| 파일 | 지키는 것 |
|---|---|
| `run.js` · `_harness.js` · `_fixtures.js` | 실행기와 공용 뼈대 |
| `01-prompts-snapshot` | 프롬프트가 한 글자도 안 바뀌었는가 |
| `02-injection` | 학생이 쓴 글이 AI 지시로 읽히지 않는가 |
| `03-grading` | 점수가 NaN이 되지 않는가, 배점 상한, 미답변 처리 |
| `04-validation` | 악용 요청이 **AI를 부르기 전에** 끊기는가 |
| `05-client` | 화면 스크립트 로드, 사진 압축, 죽은 값 재발 방지 |
| `06-consistency` | 규칙↔화면 필드 짝, BKT 상수, Node 버전, 런타임 폐기일 |
| `prompts.snapshot.json` | 프롬프트 기준 해시 |

**프롬프트를 일부러 고쳤다면** `01`이 실패하면서 바뀐 프롬프트 이름을 알려준다.
확인 후 `npm run test:update`로 기준을 갱신하고 함께 커밋한다.

## 7. 자주 쓰는 명령

```bash
# 시험 (코드 고칠 때마다)
cd functions && npm test

# 배포
firebase deploy                    # 전체
firebase deploy --only hosting     # 화면만
firebase deploy --only functions   # 서버만

# 서버 로그
firebase functions:log --only gradeAnswers -n 15

# 학생 신고 확인
node functions/list-reports.js --summary
```

> 배포가 `Timeout after 10000`으로 실패하면, 컴퓨터가 오래 쉬어서 첫 로드가 느린 것이다.
> `$env:FUNCTIONS_DISCOVERY_TIMEOUT=60`을 먼저 실행하고 다시 배포한다.

## 8. 논문에 쓰는 측정값이 나오는 곳

화면에는 안 보이고 **서버 로그로만** 관측되는 값들이다.

| 로그 | 뜻 |
|---|---|
| `개념별 판정 — 다중 태그 N문항 중 M건에서 판정이 갈림` | 한 서술을 오개념별로 나눠 판정하는 설계가 실제로 작동하는지. M이 계속 0이면 전제가 깨진 것 |
| `미답변 문항 가점 차단 N건` | AI가 "안 쓴 문항은 0점" 지시를 어긴 횟수. 안 뜨면 잘 지킨 것 |
| `라벨 대조 불일치 N건` | 문제를 만든 판정과 채점 판정이 갈린 문항 수 = 문항 오류율 |

모든 줄에 `unit`과 `level`이 함께 찍히므로 단원별·레벨별로 나눠 집계할 수 있다.
