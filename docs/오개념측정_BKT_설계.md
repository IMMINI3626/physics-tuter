# Phase 3 — 오개념 숙달도 측정 (Bayesian Knowledge Tracing) 설계

> 논문 작성용 설계 문서. 구현 이력은 CHANGELOG.md, 이 문서는 "무엇을 왜 어떻게 측정하는가"의
> 이론적 배경과 설계 근거를 기록한다. 구현이 진행되면 결정 사항을 이 문서에 갱신한다.
>
> 작성 시작: 2026-07 (구현 착수 전)

## 0. 이 문서의 목적

현재 시스템은 학습자의 개념 숙달을 "정답 횟수"로 근사한다. 이 방식의 한계를 분석하고,
이를 학습자 모델(learner model) 기반의 확률적 숙달도 추정으로 대체하는 설계를 기록한다.
논문의 "학습자 모델링" 또는 "숙달도 추정" 챕터의 기반 자료로 사용한다.

> 인용 표기(저자·연도·지면)는 잘 알려진 1차 문헌 기준으로 적었으나, 최종 논문 제출 전
> 서지 정보(권·호·페이지)를 원문으로 재확인할 것.

## 1. 문제 정의 — 현재 승급 방식의 한계

### 1-1. 현재 방식

레벨 승급은 "같은 소단원의 새 문제를 목표 횟수만큼 맞히면" 이뤄진다. 목표 횟수는 고정이
아니라 소단원의 오개념 수에 비례해 계산한다(`public/js/feedback.js`, `calcPromotionTarget`).

```
목표치 = clamp( round(오개념수 × 배수), 하한, 상한 )

레벨   배수    하한   상한
L1     1.7     10     20
L2     1.3      7     13
L3     1.0      5     10
```

즉 오개념 13개인 소단원의 L1 목표는 round(13 × 1.7)=22 → 상한 20, 오개념 3개짜리는
round(3 × 1.7)=5 → 하한 10. 소단원마다 목표가 달라진다.

### 1-2. 두 가지 근본적 한계

(1) **계수의 임의성.** "오개념 수에 비례한다"는 방향 자체는 타당하나, 비례 계수(1.7, 1.3,
1.0)와 상하한(20, 13, 10 …)에는 이론적·경험적 근거가 없다. 심사·논문 방어 시
"왜 1.7인가", "왜 상한 20인가"에 답할 수 없다.

(2) **"이해"가 아니라 "횟수"를 센다.** 정답 하나하나를 동일한 1회로 계산한다. 그러나
   - 찍어서 맞힌 정답과 완전히 이해하고 맞힌 정답,
   - 힌트를 보고 맞힌 정답과 스스로 맞힌 정답,
   - 개념을 알면서 실수로 틀린 오답과 정말 몰라서 틀린 오답
   이 모두 구분되지 않는다. 힌트 감점(Phase 2, 6-3)으로 일부 완화했으나 근본 해결은 아니다.

결과적으로 "이 학습자가 이 개념을 이해했는가?"라는 질문에 시스템이 정량적으로 답하지 못한다.
과거 마이페이지의 "교정된 오개념" 통계가 근거 부족으로 제거된 것(CHANGELOG 2-4)도 같은 원인이다.

## 2. 이론적 배경

### 2-1. 숙달 학습과 형성평가

- **숙달 학습(Mastery Learning; Bloom, 1968).** 다음 단계로 넘어가기 전에 현재 개념을
  일정 수준 이상 숙달하도록 요구하는 교수 전략. 본 시스템의 레벨 승급 구조가 이 틀에 해당한다.
- **형성평가(Formative Assessment; Black & Wiliam, 1998).** 학습 과정 중 학습자의 상태를
  진단해 후속 학습을 조정하는 평가. 본 시스템은 "진단 → 맞춤 문제 → 재진단"의 형성평가 루프다.

현재 방식의 문제는 "숙달 수준"을 정답 횟수라는 대리 지표로만 측정한다는 점이다. 숙달을
직접 추정하려면 학습자 모델이 필요하다.

### 2-2. 지능형 교수 시스템과 학습자 모델

- **지능형 교수 시스템(Intelligent Tutoring System, ITS; VanLehn, 2011).** 학습자의 상태를
  모델링해 개별화된 피드백·문제를 제공하는 시스템. 그 핵심 구성요소가 **학습자 모델
  (learner/student model)** — "학습자가 각 지식 요소를 얼마나 아는가"의 내부 표상.
- 본 시스템은 이미 ITS의 요소를 갖는다(오개념 진단, 맞춤 문제 생성, 교정 루프). 그러나
  학습자 모델은 없다. 세션에 총점만 남을 뿐, 개념별 지식 상태를 추적하지 않는다.

### 2-3. 지식 추적과 BKT

- **지식 추적(Knowledge Tracing).** 학습자가 문제를 풀 때마다 관측(정오답)으로부터 잠재된
  지식 상태를 추정·갱신하는 문제.
- **Bayesian Knowledge Tracing(BKT; Corbett & Anderson, 1994).** 각 지식 요소(skill)의 숙달
  여부를 이진 잠재변수로 두고, 정오답 관측마다 베이즈 정리로 "숙달했을 확률 P(L)"을
  갱신하는 모델. 은닉 마르코프 모델(HMM)의 한 형태다. 교육공학에서 30년간 널리 쓰인 표준이다.
- BKT의 강점은 **찍음(guess)과 실수(slip)를 명시적으로 모형화**한다는 점이다 — 1-2절의
  (2) 한계를 정확히 겨냥한다.

> 향후 확장 참고: Deep Knowledge Tracing(DKT; Piech et al., 2015) 등 신경망 기반 지식 추적도
> 있으나, 해석 가능성·데이터 요구량·구현 난도를 고려하면 학부 졸업작품에는 BKT가 적합하다.
> BKT는 파라미터 4개의 의미가 명확해 "왜 이 판정이 나왔는가"를 설명할 수 있다.

### 2-4. 물리 오개념 진단의 근거 (기존 자산)

본 시스템의 오개념 DB는 표준 진단도구에 기반한다. 이는 BKT의 "지식 요소" 정의에 그대로 쓰인다.

- **FCI(Force Concept Inventory; Hestenes, Wells & Swackhamer, 1992).** 역학 오개념 진단의
  표준 검사. 본 시스템 unit1 오개념의 근거.
- **FMCE(Force and Motion Conceptual Evaluation; Thornton & Sokoloff, 1998).** 뉴턴 역학
  개념 평가. FCI와 함께 역학 오개념 체계의 근거.
- 그 외 국내 석·박사 학위논문 기반으로 전자기·파동·양자 오개념을 확장(CHANGELOG "시딩 이력" 참고).

## 3. BKT 이론 상세

### 3-1. 네 개의 파라미터

각 지식 요소(본 시스템에서는 오개념 또는 개념 영역)마다 다음 네 값을 둔다.

| 기호 | 이름 | 의미 | 범위 |
|------|------|------|------|
| P(L₀) | 초기 지식 (prior) | 학습 이전에 이미 숙달했을 확률 | 0~1 |
| P(T)  | 학습률 (transit) | 한 번의 학습 기회로 미숙달→숙달로 전이할 확률 | 0~1 |
| P(G)  | 추측 (guess) | 숙달하지 못했는데도 정답을 낼 확률 | 보통 0~0.3 |
| P(S)  | 실수 (slip) | 숙달했는데도 오답을 낼 확률 | 보통 0~0.1 |

P(L)은 "현재 숙달했을 확률"로, 관측이 쌓일수록 갱신된다. P(L₀)는 그 시작값이다.

### 3-2. 갱신 수식

관측(정답/오답)을 본 뒤, 먼저 베이즈 정리로 사후확률을 구한다(관측 반영).

정답을 관측한 경우:

```
                     P(Lₙ₋₁)·(1−P(S))
P(Lₙ₋₁ | 정답) = ─────────────────────────────────────
                 P(Lₙ₋₁)·(1−P(S)) + (1−P(Lₙ₋₁))·P(G)
```

오답을 관측한 경우:

```
                     P(Lₙ₋₁)·P(S)
P(Lₙ₋₁ | 오답) = ─────────────────────────────────────
                 P(Lₙ₋₁)·P(S) + (1−P(Lₙ₋₁))·(1−P(G))
```

그 다음 학습 전이를 반영해 다음 상태의 숙달 확률을 얻는다(학습 반영).

```
P(Lₙ) = P(Lₙ₋₁ | 관측) + (1 − P(Lₙ₋₁ | 관측))·P(T)
```

(참고) 다음 문항을 맞힐 것으로 예측되는 확률:

```
P(정답ₙ) = P(Lₙ₋₁)·(1−P(S)) + (1−P(Lₙ₋₁))·P(G)
```

### 3-3. 수치 예시 (검증용)

파라미터를 P(L₀)=0.30, P(T)=0.15, P(G)=0.20, P(S)=0.10으로 두고, 한 학습자가 특정 개념
문항을 정·정·오·정·정 순으로 풀었다고 하자. 숙달 확률 P(L)의 변화:

| 문항 | 관측 | 갱신 후 P(L) |
|------|------|:---:|
| 시작 | —    | 0.30 |
| 1    | 정답 | 0.71 |
| 2    | 정답 | 0.93 |
| 3    | 오답 | 0.68 |
| 4    | 정답 | 0.92 |
| 5    | 정답 | 0.98 |

정답이 쌓이면 확률이 부드럽게 상승하고, 오답에서 하락한 뒤 회복한다. 5번째에서 0.95를
넘어 "숙달"로 판정된다. (계산 예시이며 파라미터·문항 순서에 따라 값은 달라진다.)

이 표는 "정답 횟수 세기"가 흉내 낼 수 없는 두 성질을 보여준다.
- 같은 "정답"이어도 현재 P(L)에 따라 상승폭이 다르다(이미 확신이 높으면 조금만 오른다).
- 오답 하나가 확률을 크게 되돌리므로, 우연한 연속 정답만으로는 쉽게 숙달 판정이 나지 않는다.

## 4. 본 시스템 적용 설계 (확정)

아래는 2026-07 설계 논의로 확정된 사항이다. (L3 핵심 선정만 A→C 단계적 적용)

### 4-1. 지식 요소의 단위 — 오개념 단위로 추적, 개념 영역으로 표시 (확정)

- **BKT는 개별 오개념(87개) 단위로 P(L)을 추적한다.** 각 오개념마다 이해도 확률을 하나씩 가진다.
- **화면 표시는 개념 영역(17개 dimension)으로 롤업**한다. Phase 2 "집중하면 좋을 개념"(6-2)의
  롤업을 재사용해, 오개념별 P(L)의 평균 등으로 영역 이해도를 보여준다.
- 즉 "측정·저장은 오개념, 표시는 영역". 오개념 단위로 추적해야 순환 출제(약한 오개념 우선)와
  L2/L3 대상 선정이 가능하다.

### 4-2. 레벨과의 관계 — 레벨 = 소단원 전체 난이도, 위로 갈수록 범위 축소 (확정)

레벨(L1/L2/L3)은 **문제 난이도**이며 **소단원 전체가 하나로** 한 방향(L1→L2→L3)으로만 올라간다.
오개념마다 레벨이 따로 있지 않다. 위 레벨로 갈수록 다루는 오개념 범위를 좁힌다.

| 레벨 | 유형(기존 그대로) | 대상 오개념 | 승급 조건 |
|------|------------------|-------------|-----------|
| L1 | 문장 5개(정성+공식) | 소단원 **전체** | 전체 오개념 P(L) ≥ 0.90 |
| L2 | 계산 단답/판별 | **약점만** (아래 4-4) | 그 약점들 P(L) ≥ 0.90 |
| L3 | 복합 계산 | **핵심 약점만** (아래 4-4) | 그 핵심들 P(L) ≥ 0.90 |

- L1에서 전체를 다루므로, 사진 찍지 않은 오개념도 반드시 다뤄진다("건너뛰기" 방지).
- 오개념 수에 문제량이 자연스럽게 비례한다(3개≈10문제 / 10개≈29 / 17개≈48). 임의 계수 없이.

### 4-3. BKT 파라미터·초기값·임계값 (확정)

```
P(T) = 0.15   (학습률)
P(G) = 0.20   (추측)   — 힌트 사용 시 correct 관측에 한해 0.50으로 상향(아래 4-6)
P(S) = 0.10   (실수)
τ    = 0.90   (숙달 기준)

초기 P(L₀):
  진단검사에서 오답 / 사진에서 진단됨   → 0.15  (약점 확인)
  진단검사에서 정답                    → 0.70  (아마 앎)
  아무데도 안 걸림                     → 0.30  (미지)
```

τ는 0.95 대신 0.90으로 낮춘다. 이때 한 오개념 극복에 필요한 연속 정답은 초기값별로 1~3회
(0.70→1, 0.30→2, 0.15→3)로, 단원 완주가 현실적 범위(≈10~48문제)에 든다.

### 4-4. L2/L3 대상 오개념 선정 (확정: 가+나 / A, 추후 C)

- **L2 약점** = **(가) 사진에서 진단된 것 OR (나) L1 종료 시 이해도가 낮았던 하위 N개**.
  둘의 합집합. "학생이 교과서에서 헷갈린 것 + 실제로 못 잡은 것"을 모두 계산 수준으로 검증.
- **L3 핵심** = **(방법 A) L2 종료 시에도 이해도가 낮게 남은 하위 N개** (잔여 약점).
  "여러 레벨을 거치고도 못 잡은 오개념을 최상위 난이도로 최종 검증".
  - 추후 **방법 C**로 확장: A(잔여 약점) AND B(복합 계산 가능한 개념)로 교차. B는 오개념에
    "복합형 가능" 태그가 필요해 준비 작업이 있어 지금은 A만. (`question_patterns`의
    difficultyHint '상'과 연결 예정)

### 4-5. 사전 진단검사 (확정)

- 소단원 첫 진입 시, 그 소단원의 `misconception_sentences`에서 **문장 5개**를 뽑아
  "맞다/틀리다"로 판별하게 한다. (전수조사 아님 — 표본)
- 각 문장은 오개념 id로 태깅돼 있으므로, 판별 결과로 해당 오개념의 초기 P(L)을 세팅한다
  (제대로 판별 → 0.70, 틀리게 판별 → 0.15). 안 물어본 오개념은 0.30.
- **모든 소단원(역학/비역학 무관)에서 동일 작동** — misconception_sentences가 전 단원에 있음.
- FCI/FMCE(역학 전용)는 진단검사가 아니라 **사전-사후 효과 검증 실험**용 표준 도구로 별도 활용.

### 4-6. 힌트의 반영 (확정)

힌트를 보고 맞힌 정답은 "스스로 앎"의 증거가 약하다. **correct 관측에 한해 P(G)를 0.20 →
0.50으로 상향**해 그 정답의 증거력을 할인한다(오답 관측은 기본 P(G) 유지). Phase 2의 임의 감점
(6-3)을 관측 신뢰도 조정으로 대체·정당화한다.

### 4-7. 진단된 오개념 풀 (확정)

- 사진 분석 성공 시, 진단된 오개념 id를 소단원별 "풀"에 **누적(합집합)**하고 그 오개념의
  P(L)을 0.15로 낮춘다(약점 확인). 사진을 여러 장 찍으면 풀이 커진다.
- 이어서 풀기는 이 풀 + 이해도 낮은 오개념을 우선 대상으로 삼는다.
- Phase 2 6-5의 "마지막 진단 물려받기"를 이 누적 풀로 대체.

### 4-8. 순환 출제 (확정)

다음 문제가 겨냥할 오개념 선택:
1. 현재 레벨의 대상 오개념 중 아직 숙달 안 된 것(P(L) < 0.90)만 후보.
2. 후보를 P(L) 오름차순 정렬(약한 것 먼저).
3. 상위 1~2개를 겨냥한 문제를 생성(STEP1/2는 오답 문장으로, 계산형은 문제 소재로).

### 4-9. 데이터 구조 변경

```
(신규) 사용자별 오개념 숙달 상태 — BKT의 P(L) 보관
/users/{uid}/knowledgeState/{오개념id}
  pL: number          // 현재 이해도 확률
  attempts: number    // 관측 수
  lastUpdated: timestamp

(추가) 소단원 진행 정보
/users/{uid}/unitProgress/{소단원}
  level: 1|2|3                          // 현재 난이도 (기존 유지)
  diagnosedMisconceptions: string[]     // 사진 진단 누적 풀 (신규)
  diagnosticDone: boolean               // 사전 진단검사 완료 여부 (신규)
  (제거 예정) correctCount              // 횟수 카운터 → P(L)로 대체

(추가) 문항 로그
/users/{uid}/sessions/{sid}/logs/{logId}
  targetMisconceptionId: string   // 이 문항이 겨냥한 오개념 (신규)
  isCorrect: boolean              // 그 문항 정오답 (신규)
  usedHint: boolean               // 힌트 사용 여부 (신규)
```

승급 판정(feedback.js)은 "correctCount 비교"에서 "현재 레벨 대상 오개념의 knowledgeState.pL이
모두 τ 이상인지 확인"으로 바뀐다. `calcPromotionTarget`(임의 계수)은 제거된다.

## 5. 기존 방식과의 비교 (논문 표 초안)

| 항목 | 현재 (횟수 기반) | Phase 3 (BKT) |
|------|------------------|----------------|
| 측정 대상 | 정답 횟수 | 개념 숙달 확률 P(L) |
| 찍음/실수 | 구분 못 함 | P(G)/P(S)로 명시적 모형화 |
| 힌트 | 임의 감점 | 관측 신뢰도(P(G)) 조정 |
| 승급 기준 | 목표 횟수(임의 계수 1.7 등) | P(L) ≥ 0.90 (이론적 기준) |
| 이론적 근거 | 없음 | Corbett & Anderson (1994) |
| 학습자 모델 | 없음(총점만) | 개념별 지식 상태 표상 |
| "교정된 오개념" 통계 | 근거 부족으로 제거됨 | P(L) 상승분으로 정량화 가능 |

## 6. 논문에서의 기여점 (서술 방향)

- 생성형 AI로 물리 오개념 진단·문제 생성을 하는 시스템에, **표준 학습자 모델(BKT)을 결합**해
  개념 숙달을 확률적으로 추정하고 숙달 기반으로 학습을 개별화했다.
- 이로써 "AI가 문제를 만들어 줄 뿐"이라는 한계를 넘어, **학습자 모델링이라는 독립적 공학 기여**를
  갖는다. (핵심 로직이 프롬프트가 아니라 시스템 내부에 있다.)
- FCI/FMCE 기반 오개념 체계를 BKT의 지식 요소로 사용해, 진단도구의 타당성을 모델의 단위로
  이어받았다.

## 7. 한계 및 향후 과제

- BKT는 각 지식 요소의 독립을 가정한다. 실제 물리 개념은 선수관계가 있어(Phase 4의 선수관계
  그래프와 연결점), 이를 반영하는 확장은 향후 과제.
- 파라미터를 고정값으로 두면 개념별 난이도 차이를 반영하지 못한다. 데이터 적합(EM) 또는
  민감도 분석이 향후 과제.
- 효과 검증: 사전-사후 개념검사(FCI 축약본 등)로 BKT 숙달 판정과 실제 학습 성취의 상관을
  측정하는 실험을 논문 평가 장에 배치.

## 8. 구현 단계

기존 승급/채점 흐름을 통째로 갈아끼우는 큰 변경이라, 앱을 깨지 않도록 아래 순서로
점진적으로 구현한다(안전·순수한 것 먼저, 흐름 재배선은 나중).

```
[x] 0. BKT 계산 핵심 모듈 (public/js/bkt.js) — 순수 함수, 단위 테스트 완료
        update(pL, isCorrect, {usedHint}), isMastered(pL), 초기값 상수
[ ] 1. 문항별 오개념 태깅 — generateQuestions가 문항에 targetMisconceptionId 반환 + 검증
[ ] 2. 채점 로그 확장 — logs에 targetMisconceptionId/isCorrect/usedHint 저장
[ ] 3. knowledgeState 저장/조회 (firestore.js) — 오개념별 P(L) 영속화
[ ] 4. 관측 반영 — 채점 후 겨냥 오개념의 P(L)을 BKT로 갱신
[ ] 5. 진단된 오개념 풀 — 사진 성공 시 unitProgress에 누적, 이어서 풀기가 사용
[ ] 6. 순환 출제 — 현재 레벨 대상 중 P(L) 낮은 오개념 우선 선택
[ ] 7. 승급 판정 교체 — calcPromotionTarget → 레벨 대상 오개념 P(L) ≥ τ
[ ] 8. 사전 진단검사 화면 — 문장 5개로 초기 P(L) 세팅
[ ] 9. 마이페이지 표시 — 오개념/영역 이해도 % 시각화, "교정된 오개념" 통계 복원
[ ] 10. (검증) 수치 검증 + 파라미터 민감도 분석 (논문 실험)
```
