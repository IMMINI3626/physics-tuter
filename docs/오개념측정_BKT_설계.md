## 0. 이 문서의 목적

현재 시스템은 학습자의 개념 숙달을 "정답 횟수"로 근사한다. 이 방식의 한계를 분석하고,
이를 학습자 모델(learner model) 기반의 확률적 숙달도 추정으로 대체하는 설계를 기록한다.
논문의 "학습자 모델링" 또는 "숙달도 추정" 챕터의 기반 자료로 사용한다.

> 인용 표기(저자·연도·지면)는 잘 알려진 1차 문헌 기준으로 적었으나, 최종 논문 제출 전
> 서지 정보(권·호·페이지)를 원문으로 재확인할 것.

## 1. 문제 정의 — 현재 승급 방식의 한계

### 1-1. 현재 방식

레벨 승급은 "같은 소단원의 새 문제를 목표 횟수만큼 맞히면" 이뤄진다. 목표 횟수는 고정이
아니라 소단원의 오개념 수에 비례해 계산한다(`public/js/feedback.js`, `calcPromotionTarget`).

```
목표치 = clamp( round(오개념수 × 배수), 하한, 상한 )

레벨   배수    하한   상한
L1     1.7     10     20
L2     1.3      7     13
L3     1.0      5     10
```

즉 오개념 13개인 소단원의 L1 목표는 round(13 × 1.7)=22 → 상한 20, 오개념 3개짜리는
round(3 × 1.7)=5 → 하한 10. 소단원마다 목표가 달라진다.

### 1-2. 두 가지 근본적 한계

(1) **계수의 임의성.** "오개념 수에 비례한다"는 방향 자체는 타당하나, 비례 계수(1.7, 1.3,
1.0)와 상하한(20, 13, 10 …)에는 이론적·경험적 근거가 없다. 심사·논문 방어 시
"왜 1.7인가", "왜 상한 20인가"에 답할 수 없다.

(2) **"이해"가 아니라 "횟수"를 센다.** 정답 하나하나를 동일한 1회로 계산한다. 그러나
   - 찍어서 맞힌 정답과 완전히 이해하고 맞힌 정답,
   - 힌트를 보고 맞힌 정답과 스스로 맞힌 정답,
   - 개념을 알면서 실수로 틀린 오답과 정말 몰라서 틀린 오답
   이 모두 구분되지 않는다. 힌트 감점(Phase 2, 6-3)으로 일부 완화했으나 근본 해결은 아니다.

결과적으로 "이 학습자가 이 개념을 이해했는가?"라는 질문에 시스템이 정량적으로 답하지 못한다.
과거 마이페이지의 "교정된 오개념" 통계가 근거 부족으로 제거된 것(CHANGELOG 2-4)도 같은 원인이다.

## 2. 이론적 배경

### 2-1. 숙달 학습과 형성평가

- **숙달 학습(Mastery Learning; Bloom, 1968).** 다음 단계로 넘어가기 전에 현재 개념을
  일정 수준 이상 숙달하도록 요구하는 교수 전략. 본 시스템의 레벨 승급 구조가 이 틀에 해당한다.
- **형성평가(Formative Assessment; Black & Wiliam, 1998).** 학습 과정 중 학습자의 상태를
  진단해 후속 학습을 조정하는 평가. 본 시스템은 "진단 → 맞춤 문제 → 재진단"의 형성평가 루프다.

현재 방식의 문제는 "숙달 수준"을 정답 횟수라는 대리 지표로만 측정한다는 점이다. 숙달을
직접 추정하려면 학습자 모델이 필요하다.

### 2-2. 지능형 교수 시스템과 학습자 모델

- **지능형 교수 시스템(Intelligent Tutoring System, ITS; VanLehn, 2011).** 학습자의 상태를
  모델링해 개별화된 피드백·문제를 제공하는 시스템. 그 핵심 구성요소가 **학습자 모델
  (learner/student model)** — "학습자가 각 지식 요소를 얼마나 아는가"의 내부 표상.
- 본 시스템은 이미 ITS의 요소를 갖는다(오개념 진단, 맞춤 문제 생성, 교정 루프). 그러나
  학습자 모델은 없다. 세션에 총점만 남을 뿐, 개념별 지식 상태를 추적하지 않는다.

### 2-3. 지식 추적과 BKT

- **지식 추적(Knowledge Tracing).** 학습자가 문제를 풀 때마다 관측(정오답)으로부터 잠재된
  지식 상태를 추정·갱신하는 문제.
- **Bayesian Knowledge Tracing(BKT; Corbett & Anderson, 1994).** 각 지식 요소(skill)의 숙달
  여부를 이진 잠재변수로 두고, 정오답 관측마다 베이즈 정리로 "숙달했을 확률 P(L)"을
  갱신하는 모델. 은닉 마르코프 모델(HMM)의 한 형태다. 교육공학에서 30년간 널리 쓰인 표준이다.
- BKT의 강점은 **찍음(guess)과 실수(slip)를 명시적으로 모형화**한다는 점이다 — 1-2절의
  (2) 한계를 정확히 겨냥한다.

> 향후 확장 참고: Deep Knowledge Tracing(DKT; Piech et al., 2015) 등 신경망 기반 지식 추적도
> 있으나, 해석 가능성·데이터 요구량·구현 난도를 고려하면 학부 졸업작품에는 BKT가 적합하다.
> BKT는 파라미터 4개의 의미가 명확해 "왜 이 판정이 나왔는가"를 설명할 수 있다.

### 2-4. 물리 오개념 진단의 근거 (기존 자산)

본 시스템의 오개념 DB는 표준 진단도구에 기반한다. 이는 BKT의 "지식 요소" 정의에 그대로 쓰인다.

- **FCI(Force Concept Inventory; Hestenes, Wells & Swackhamer, 1992).** 역학 오개념 진단의
  표준 검사. 본 시스템 unit1 오개념의 근거.
- **FMCE(Force and Motion Conceptual Evaluation; Thornton & Sokoloff, 1998).** 뉴턴 역학
  개념 평가. FCI와 함께 역학 오개념 체계의 근거.
- 그 외 국내 석·박사 학위논문 기반으로 전자기·파동·양자 오개념을 확장(CHANGELOG "시딩 이력" 참고).

## 3. BKT 이론 상세

### 3-1. 네 개의 파라미터

각 지식 요소(본 시스템에서는 오개념 또는 개념 영역)마다 다음 네 값을 둔다.

| 기호 | 이름 | 의미 | 범위 |
|------|------|------|------|
| P(L₀) | 초기 지식 (prior) | 학습 이전에 이미 숙달했을 확률 | 0~1 |
| P(T)  | 학습률 (transit) | 한 번의 학습 기회로 미숙달→숙달로 전이할 확률 | 0~1 |
| P(G)  | 추측 (guess) | 숙달하지 못했는데도 정답을 낼 확률 | 보통 0~0.3 |
| P(S)  | 실수 (slip) | 숙달했는데도 오답을 낼 확률 | 보통 0~0.1 |

P(L)은 "현재 숙달했을 확률"로, 관측이 쌓일수록 갱신된다. P(L₀)는 그 시작값이다.

### 3-2. 갱신 수식

관측(정답/오답)을 본 뒤, 먼저 베이즈 정리로 사후확률을 구한다(관측 반영).

정답을 관측한 경우:

```
                     P(Lₙ₋₁)·(1−P(S))
P(Lₙ₋₁ | 정답) = ─────────────────────────────────────
                 P(Lₙ₋₁)·(1−P(S)) + (1−P(Lₙ₋₁))·P(G)
```

오답을 관측한 경우:

```
                     P(Lₙ₋₁)·P(S)
P(Lₙ₋₁ | 오답) = ─────────────────────────────────────
                 P(Lₙ₋₁)·P(S) + (1−P(Lₙ₋₁))·(1−P(G))
```

그 다음 학습 전이를 반영해 다음 상태의 숙달 확률을 얻는다(학습 반영).

```
P(Lₙ) = P(Lₙ₋₁ | 관측) + (1 − P(Lₙ₋₁ | 관측))·P(T)
```

(참고) 다음 문항을 맞힐 것으로 예측되는 확률:

```
P(정답ₙ) = P(Lₙ₋₁)·(1−P(S)) + (1−P(Lₙ₋₁))·P(G)
```

### 3-3. 수치 예시 (검증용)

파라미터를 P(L₀)=0.30, P(T)=0.15, P(G)=0.20, P(S)=0.10으로 두고, 한 학습자가 특정 개념
문항을 정·정·오·정·정 순으로 풀었다고 하자. 숙달 확률 P(L)의 변화:

| 문항 | 관측 | 갱신 후 P(L) |
|------|------|:---:|
| 시작 | —    | 0.30 |
| 1    | 정답 | 0.71 |
| 2    | 정답 | 0.93 |
| 3    | 오답 | 0.68 |
| 4    | 정답 | 0.92 |
| 5    | 정답 | 0.98 |

정답이 쌓이면 확률이 부드럽게 상승하고, 오답에서 하락한 뒤 회복한다. 5번째에서 0.95를
넘어 "숙달"로 판정된다. (계산 예시이며 파라미터·문항 순서에 따라 값은 달라진다.)

이 표는 "정답 횟수 세기"가 흉내 낼 수 없는 두 성질을 보여준다.
- 같은 "정답"이어도 현재 P(L)에 따라 상승폭이 다르다(이미 확신이 높으면 조금만 오른다).
- 오답 하나가 확률을 크게 되돌리므로, 우연한 연속 정답만으로는 쉽게 숙달 판정이 나지 않는다.

## 4. 본 시스템 적용 설계 (확정)

아래는 2026-07 설계 논의로 확정된 사항이다. (L3 핵심 선정만 A→C 단계적 적용)

### 4-1. 지식 요소의 단위 — 오개념 단위로 추적, 개념 영역으로 표시 (확정)

- **BKT는 개별 오개념(87개) 단위로 P(L)을 추적한다.** 각 오개념마다 이해도 확률을 하나씩 가진다.
- **화면 표시는 개념 영역(17개 dimension)으로 롤업**한다. Phase 2 "집중하면 좋을 개념"(6-2)의
  롤업을 재사용해, 오개념별 P(L)의 평균 등으로 영역 이해도를 보여준다.
- 즉 "측정·저장은 오개념, 표시는 영역". 오개념 단위로 추적해야 순환 출제(약한 오개념 우선)와
  L2/L3 대상 선정이 가능하다.

### 4-2. 레벨과의 관계 — 레벨 = 소단원 전체 난이도, 위로 갈수록 범위 축소 (확정)

레벨(L1/L2/L3)은 **문제 난이도**이며 **소단원 전체가 하나로** 한 방향(L1→L2→L3)으로만 올라간다.
오개념마다 레벨이 따로 있지 않다. 위 레벨로 갈수록 다루는 오개념 범위를 좁힌다.

| 레벨 | 유형(기존 그대로) | 대상 오개념 | 승급 조건 |
|------|------------------|-------------|-----------|
| L1 | 문장 5개(정성+공식) | 소단원 **전체** | 전체 오개념 P(L) ≥ 0.90 |
| L2 | 계산 단답/판별 | **약점만** (아래 4-4) | 그 약점들 P(L) ≥ 0.90 |
| L3 | 복합 계산 | **핵심 약점만** (아래 4-4) | 그 핵심들 P(L) ≥ 0.90 |

- L1에서 전체를 다루므로, 사진 찍지 않은 오개념도 반드시 다뤄진다("건너뛰기" 방지).
- 오개념 수에 문제량이 자연스럽게 비례한다(3개≈10문제 / 10개≈29 / 17개≈48). 임의 계수 없이.

### 4-3. BKT 파라미터·초기값·임계값 (확정)

```
P(T) = 0.15   (학습률)
P(G) = 0.20   (추측)   — 힌트 사용 시 correct 관측에 한해 0.50으로 상향(아래 4-6)
P(S) = 0.10   (실수)
τ    = 0.90   (숙달 기준)

초기 P(L₀):
  사진에서 진단됨      → 0.15  (약점 확인)
  아무 증거 없음       → 0.30  (미지) — 모든 오개념의 출발점
```

τ는 0.95 대신 0.90으로 낮춘다. 이때 한 오개념 극복에 필요한 연속 정답은 초기값별로 1~3회
(0.30→2, 0.15→3)로, 단원 완주가 현실적 범위(≈10~48문제)에 든다.

> **폐기된 초기값**: 진단검사 정답 → 0.70, 진단검사 오답 → 0.15로 두는 안을 처음 설계했으나
> 단계 8에서 폐기했다. 진단 문항은 O/X 이지선다라 0.70은 "찍기 한 번 + 문제 한 번"으로 숙달에
> 닿아 10%가 운으로 통과했다. 지금은 진단 결과를 초기값이 아니라 **추측률 0.50짜리 관측 한 건**
> 으로 처리한다(4-11). 손으로 정하는 초기값 파라미터가 P(L₀)=0.30 하나로 줄어든다.

### 4-4. L2/L3 대상 오개념 선정 (단계 7에서 4-10으로 수정됨)

> 아래 (나)·(A)는 "L1/L2를 마쳐도 미숙달 오개념이 남는다"는 전제였다. 단계 7에서 승급 조건을
> "레벨 대상 전부 숙달"로 확정하면서 그 잔여 집합이 공집합이 되므로, 실제 구현은 4-10을 따른다.
> (L2/L3 대상 = 사진으로 진단된 풀, 난이도 상승은 이해도 재설정으로 반영)

- **L2 약점** = **(가) 사진에서 진단된 것 OR (나) L1 종료 시 이해도가 낮았던 하위 N개**.
  둘의 합집합. "학생이 교과서에서 헷갈린 것 + 실제로 못 잡은 것"을 모두 계산 수준으로 검증.
- **L3 핵심** = **(방법 A) L2 종료 시에도 이해도가 낮게 남은 하위 N개** (잔여 약점).
  "여러 레벨을 거치고도 못 잡은 오개념을 최상위 난이도로 최종 검증".
  - 추후 **방법 C**로 확장: A(잔여 약점) AND B(복합 계산 가능한 개념)로 교차. B는 오개념에
    "복합형 가능" 태그가 필요해 준비 작업이 있어 지금은 A만. (`question_patterns`의
    difficultyHint '상'과 연결 예정)

### 4-5. 사전 진단검사 (확정)

- 소단원 첫 진입 시, 그 소단원의 `misconception_sentences`에서 **문장 5개**를 뽑아
  "맞다/틀리다"로 판별하게 한다. (전수조사 아님 — 표본)
- 각 문장은 오개념 id로 태깅돼 있으므로, 판별 결과로 해당 오개념의 초기 P(L)을 세팅한다
  (제대로 판별 → 0.70, 틀리게 판별 → 0.15). 안 물어본 오개념은 0.30.
- **모든 소단원(역학/비역학 무관)에서 동일 작동** — misconception_sentences가 전 단원에 있음.
- FCI/FMCE(역학 전용)는 진단검사가 아니라 **사전-사후 효과 검증 실험**용 표준 도구로 별도 활용.

### 4-6. 힌트의 반영 (확정)

힌트를 보고 맞힌 정답은 "스스로 앎"의 증거가 약하다. **correct 관측에 한해 P(G)를 0.20 →
0.50으로 상향**해 그 정답의 증거력을 할인한다(오답 관측은 기본 P(G) 유지). Phase 2의 임의 감점
(6-3)을 관측 신뢰도 조정으로 대체·정당화한다.

### 4-7. 진단된 오개념 풀 (확정)

- 사진 분석 성공 시, 진단된 오개념 id를 소단원별 "풀"에 **누적(합집합)**하고 그 오개념의
  P(L)을 0.15로 낮춘다(약점 확인). 사진을 여러 장 찍으면 풀이 커진다.
- 이어서 풀기는 이 풀 + 이해도 낮은 오개념을 우선 대상으로 삼는다.
- Phase 2 6-5의 "마지막 진단 물려받기"를 이 누적 풀로 대체.

### 4-8. 순환 출제 (확정)

다음 문제가 겨냥할 오개념 선택:
1. 현재 레벨의 대상 오개념 중 아직 숙달 안 된 것(P(L) < 0.90)만 후보.
2. 후보를 P(L) 오름차순 정렬(약한 것 먼저).
3. 상위 1~2개를 겨냥한 문제를 생성(STEP1/2는 오답 문장으로, 계산형은 문제 소재로).

### 4-10. 승급 판정 (확정, 단계 7)

레벨별 대상 오개념

| 레벨 | 대상 | 근거 |
|---|---|---|
| L1 | 소단원 전체 오개념 | 무엇을 모르는지 아직 좁혀지지 않은 단계 — 넓게 훑는다 |
| L2 | 사진으로 진단된 풀 (비면 소단원 전체) | 학생이 실제로 교과서에서 걸린 지점을 계산 수준에서 재검증 |
| L3 | 사진으로 진단된 풀 (비면 소단원 전체) | 같은 지점을 최상위 난이도로 최종 검증 |

승급 조건 — **대상 오개념의 P(L)이 모두 0.90 이상**. 점수 만점 여부는 보지 않는다(오답은 이미
P(L)을 떨어뜨리는 형태로 반영됨). 대상이 0개면 승급시키지 않는다(데이터 누락 시 오승급 방지).

승급 시 이해도 재설정 — 쉬운 난이도의 증거는 어려운 난이도로 그대로 전이되지 않는다.
증거를 들고 가면 다음 레벨이 한두 문제로 끝나므로 사전확률을 되돌린다.

| 승급 시점 상태 | 다음 레벨 초기 P(L) |
|---|---|
| 숙달(≥ 0.90) | unknown 0.30 |
| 미숙달 | weak 0.15 |

새 상수를 도입하지 않고 4-3의 초기값을 재사용한다.

예상 문항 수 (한 문제도 안 틀린 최선 시나리오, 문항당 관측 L1·L2 2회 / L3 1회)

| 소단원 오개념 수 | 진단 풀 | L1 | L2 | L3 | 합계 |
|---|---|---|---|---|---|
| 22 (뉴턴 운동 법칙) | 3 | 24 | 3 | 6 | 33 |
| 13 (역학적 에너지 보존) | 3 | 15 | 3 | 6 | 24 |
| 8 (물체의 운동) | 2 | 9 | 2 | 4 | 15 |
| 3 (운동량과 충격량) | 1 | 4 | 2 | 2 | 8 |

기존 방식(L1 20 + L2 13 + L3 10 = 최대 43문제, 매번 만점 요구)보다 짧으면서, 소단원 크기에
비례해 자동으로 조절된다. 임의 계수(1.7 / 1.3 / 1.0, 상하한)는 사라진다.

폴백 — `misconceptions`에 오개념이 하나도 없는 소단원은 판정 대상이 없어 영원히 승급이 안 되므로,
그런 소단원에서만 예전 누적 정답 방식(목표 L1 10 / L2 7 / L3 5)을 쓴다. 단계 7-1에서 전 소단원에
오개념을 채워 현재는 발동하지 않으며, 데이터 누락에 대비한 안전망으로만 남겨둔다.

**화면 진행률은 승급 조건과 분리한다 (단계 8-3에서 수정)**

승급 조건(전부 숙달)을 그대로 진행률로 쓰면 계단이 너무 성기다. 한 문제가 겨냥하는 오개념은 2개,
숙달에는 같은 오개념에 정답 2번이 필요하므로, 오개념 N개짜리 소단원은 **앞의 N/2문제 동안 숙달이
하나도 안 나온다.** 특수 상대성 이론(8개)에서 만점 4번을 받고도 0%가 유지되는 것이 실제로 관찰됐다.

그래서 화면에는 개수 대신 임계값까지의 거리를 평균 낸 값을 쓴다.

$$\text{진행률} = \frac{1}{N}\sum_{i=1}^{N} \mathrm{clamp}\!\left(\frac{P(L_i) - P(L_0)}{\tau - P(L_0)},\, 0,\, 1\right)$$

| P(L) | 표시 | 상황 |
|---|---|---|
| 0.2171 | 0% | 진단검사 오답 |
| 0.3000 | 0% | 출발점(unknown) |
| 0.5202 | 37% | 진단검사 정답 |
| 0.7098 | 68% | 문제 정답 1회 |
| ≥ 0.90 | 100% | 숙달 |

성질 — 출발점이 정확히 0, 전 항목 숙달이 정확히 1, 오답이면 감소, 매 문제마다 이동한다.
**승급 판정은 이 값을 쓰지 않는다.** 승급은 여전히 "대상 오개념 전부 P(L) ≥ τ"만 본다.
반올림으로 100%가 나왔는데 임계값 바로 아래(0.899) 항목이 남아 있는 경우는 99%에서 막는다
(막대가 가득 찼는데 승급이 안 되는 화면을 방지).

### 4-11. 사전 진단검사 (확정, 단계 8)

소단원을 처음 시작할 때 한 번, 문장 5개를 O/X로 판단하게 해서 오개념별 초기 이해도를 세운다.

**문항 선정 규칙** (우선순위 순, `MisconceptionDB.fetchDiagnosticSet`)

| 순위 | 규칙 | 이유 |
|---|---|---|
| 1 | 문장 5개 = 서로 다른 오개념 5개 | 한 오개념에 두 번 물으면 측정 폭이 좁아진다 |
| 2 | 개념 영역(dimensionCode)을 라운드로빈으로 순회 | 한 영역에 몰리지 않게 |
| 3 | 틀린 문장 3 / 옳은 문장 2 | 전부 틀린 문장이면 "다 X" 찍기로 다 맞는다 |

규칙 2가 실제로 작동하는 건 개념 영역이 둘 이상인 3개 소단원(뉴턴 운동 법칙 5개, 물체의 운동 2개,
전류의 자기 작용 2개)뿐이다. 나머지 11개는 영역이 하나라 규칙 1·3만 적용된다.

**답을 이해도로 환산하는 방식**

진단 결과를 "정답이면 0.70" 같은 초기값으로 쓰지 않는다. 진단 문항은 O/X 이지선다라 몰라도
절반은 맞기 때문에, unknown(0.30)에서 시작해 **추측률 P(G)=0.50을 적용한 관측 한 건**을 반영한다.
문항 형식이 추측률을 정하는 경우이므로 오답 쪽 P(오답|미숙달)=1−0.50에도 같은 값을 쓴다
(힌트 할인은 정답에만 적용하는 것과 다른 점 — 4-6 참고).

| 진단 결과 | 계산된 P(L) | 숙달까지 필요한 문제 정답 |
|---|---|---|
| 정답 | 0.5202 | 2회 |
| 건너뛰기 (관측 없음) | 0.3000 | 2회 |
| 오답 | 0.2171 | 3회 |

τ=0.90·P(G)=0.20·P(S)=0.10에서는 초기값이 어디에 있든 결과가 세 칸으로만 갈린다. 이 경계가
곧 단계 10 민감도 분석의 대상이다.

| 초기 P(L) 범위 | 숙달까지 문제 정답 |
|---|---|
| 0.625 이상 | 1회 |
| 0.220 ~ 0.624 | 2회 |
| 0.220 미만 | 3회 |

**운으로 통과할 확률** — 진단 O/X 50%, 문제 추측 20%로 볼 때 폐기안(0.70)은 0.5 × 0.2 = 10%였고,
현재 방식은 0.5 × 0.2² = 2%다.

**진단검사의 효과 범위 (중요)**

진단검사는 Level 1의 총 학습량을 줄이지 않는다. 뉴턴 운동 법칙(22개 중 5개 진단, 3정답/2오답)
기준 총 관측 수는 진단 없음 44, 현재 방식 46으로 오히려 조금 늘어난다. 5개만 건드리기 때문이다.
실제 효과는 다른 데 있다.

| 효과 | 내용 |
|---|---|
| 출제 순서 | 약한 오개념을 먼저 겨냥(4-8 순환 출제의 입력이 됨) |
| L2/L3 범위 축소 | 진단 오답을 `diagnosedMisconceptions`에 넣어, 사진 없이 들어온 경우에도 범위가 좁혀진다 |
| 논문 | 사전/사후 이해도 비교의 기준선 |

Level 1 자체의 길이(오개념 22개 소단원 ≈ 24문제)는 별도 장치가 필요하며 아직 다루지 않았다.

**운영 규칙**

| 항목 | 결정 | 이유 |
|---|---|---|
| 화면 배치 | 5문항을 한 화면에 (시험지 형태) | 훑어보고 답을 고칠 수 있다. 한 문항씩 넘기면 되돌아갈 수 없고 화면 전환만 5번 |
| 제출 | 5문항 모두 표시해야 활성 (`제출하기 (3/5)`) | 무응답과 "모르겠다"를 구분하려면 건너뛰기도 명시적 선택이어야 한다 |
| 횟수 | 소단원당 1회 (`unitProgress.diagnosticDone`) | 반복하면 사전 측정이 아니게 된다 |
| 건너뛰기 | 문항별·전체 모두 허용 | 모르는 문장을 찍게 만들면 잘못된 초기값이 들어간다 |
| 정답 공개 | 안 함 | 바로 뒤에 같은 개념의 문제가 나온다 |
| 점수 표시 | 안 함 | 검사가 아니라 준비 과정으로 보이게 |
| 비로그인 | 검사 생략 | 저장할 곳이 없다 |
| 진입 지점 | 사진 분석 후 `문제 풀기 시작`, 마이페이지 `이어서 풀기` | 소단원 학습이 실제로 시작되는 두 곳 |
| 저장 순서 | 이해도 저장 → `diagnosticDone` 표시 | 중간 실패 시 다시 볼 수 있게 |

**전제조건** — `misconception_sentences`는 Firestore 규칙에 없어 클라이언트 읽기가 기본 거부돼 있었다.
정적 참조 컬렉션(`misconception_sentences`, `misconception_dimensions`)에 읽기 허용 규칙을 추가했다.
seed에 새 정적 컬렉션을 넣을 때 규칙도 같이 넣어야 한다.

## 6. 논문에서의 기여점 (서술 방향)

- 생성형 AI로 물리 오개념 진단·문제 생성을 하는 시스템에, **표준 학습자 모델(BKT)을 결합**해
  개념 숙달을 확률적으로 추정하고 숙달 기반으로 학습을 개별화했다.
- 이로써 "AI가 문제를 만들어 줄 뿐"이라는 한계를 넘어, **학습자 모델링이라는 독립적 공학 기여**를
  갖는다. (핵심 로직이 프롬프트가 아니라 시스템 내부에 있다.)
- FCI/FMCE 기반 오개념 체계를 BKT의 지식 요소로 사용해, 진단도구의 타당성을 모델의 단위로
  이어받았다.

## 7. 한계 및 향후 과제

- BKT는 각 지식 요소의 독립을 가정한다. 실제 물리 개념은 선수관계가 있어(Phase 4의 선수관계
  그래프와 연결점), 이를 반영하는 확장은 향후 과제.
- 파라미터를 고정값으로 두면 개념별 난이도 차이를 반영하지 못한다. 데이터 적합(EM) 또는
  민감도 분석이 향후 과제.
- 효과 검증: 사전-사후 개념검사(FCI 축약본 등)로 BKT 숙달 판정과 실제 학습 성취의 상관을
  측정하는 실험을 논문 평가 장에 배치.

## 8. 구현 단계

기존 승급/채점 흐름을 통째로 갈아끼우는 큰 변경이라, 앱을 깨지 않도록 아래 순서로
점진적으로 구현한다(안전·순수한 것 먼저, 흐름 재배선은 나중).

```
[x] 0. BKT 계산 핵심 모듈 (public/js/bkt.js) — 순수 함수, 단위 테스트 완료
        update(pL, isCorrect, {usedHint}), isMastered(pL), 초기값 상수
[x] 1. 문항별 오개념 태깅 — generateQuestions가 문항에 targetMisconceptionId 반환 + 검증
[x] 2. 채점 로그 확장 — logs에 targetMisconceptionId/usedHint 저장 (정오답은 기존 isCorrectAnswer 재사용)
```

## 9. 구현 진행 기록

### 단계 0 — BKT 계산 핵심 모듈 (2026-07)

`public/js/bkt.js` 신규. 오개념 하나의 이해도 P(L)을 관측마다 갱신하는 순수 함수.
파라미터·초기값·τ는 4-3의 확정값을 상수로 담았다.

- `update(pL, isCorrect, {usedHint})` — 베이즈 갱신 후 학습 전이 반영. 힌트로 맞힌 정답은
  P(G)를 0.20→0.50으로 올려 증거를 할인.
- `isMastered(pL)`, `initialPL(status)`, `pickWeakest(items, count)`(순환 출제용), `updateMany`.
- 부수효과 없음(저장·화면·승급은 다른 파일이 호출). Node/브라우저 양쪽 노출.
- 단위 테스트 26개 통과: 3-3 수치 예시 재현, τ=0.90 극복 횟수(0.15→3/0.30→2/0.70→1),
  단조성, 힌트 할인, 경계값(0/1/범위 밖), 약점 정렬. 아직 어느 화면도 호출하지 않음.

### 단계 1 — 문항별 오개념 태깅 (2026-07)

`functions/index.js`의 generateQuestions가 각 문항에 겨냥 오개념 id를 붙여 반환한다.
BKT에 넣을 "관측(어느 오개념을 맞혔나)"의 근거를 만드는 단계.

- 프롬프트의 오개념 목록에 id를 노출(`[id: I3] 설명`)하고, 답변 스키마에 targetMisconceptionId 추가.
  - STEP1/2: isWrong:true 문장마다 태깅(옳은 문장·공식/계산 판별 문장은 생략).
  - L2B·L3 계산: calcQuestion에 주 오개념 하나(선택).
- 서버 검증: 반환된 태그 중 활성 오개념 목록(validIdSet)에 실제로 있는 것만 남기고, 나머지
  (옳은 문장에 붙은 것, 목록 밖 id, 무태그)는 null로 정리. 태깅은 부가 정보라 누락·오류 시
  재시도하지 않는다(생성 안정성 우선).
- 태그 정리 로직 단위 테스트 10개 통과. 프론트는 아직 이 필드를 사용하지 않아 기존 동작 무영향.
- 미확인: AI가 문장에 실제로 올바른 오개념 id를 다는 정확도는 배포 후 실측 필요.

### 단계 2 — 채점 로그 확장 (2026-07)

태그가 채점 결과(feedbackData.items)를 거쳐 세션 로그에 저장되도록 연결했다. 이로써

- 서버 gradeAnswers: feedbackItems에 targetMisconceptionId 추가(STEP1/2, questions에서 그대로).
- 클라이언트 submitCalc(L2B)·_finalize(L3): feedbackData.items[0]에 calcQuestion의 태그 추가.
- saveSession: 각 로그에 targetMisconceptionId + usedHint(세션의 hintUsed>0) 저장. 정오답은
  기존 isCorrectAnswer를 그대로 관측 신호로 쓴다(별도 isCorrect 필드는 두지 않음).
- fetchSessionLogs: targetMisconceptionId를 반환에 포함해, "다시 풀기"로 복원해 다시 풀 때도
  관측이 이어지게 함.
- 로그 매핑 단위 테스트 11개 통과: 태그된 문항의 (오개념, 정오답, 힌트) 관측 추출, 옳은
  문장·무태그 문항 null 처리, 계산형 단일 태그, 힌트 유무.
- 데이터 경로만 깔았고(저장까지), 아직 P(L)을 갱신하진 않는다(단계 3·4).

### 단계 3 — knowledgeState 저장/조회 (2026-07)

`firestore.js`에 오개념별 이해도(`/users/{uid}/knowledgeState/{오개념id}` = pL, attempts,

- `getKnowledge(uid, id)` — 단건 조회(없으면 null → 호출부가 초기값 사용).

### 단계 4 — 관측 반영 (2026-07)

단계 0~3이 처음으로 연결되어, 문제를 풀면 실제로 이해도 P(L)이 쌓이기 시작한다.

- `LearningService.applyBktObservations(uid, items, usedHint)` 추가: feedbackData.items에서
  태그된 관측만 골라 오개념별로 묶고, 각 오개념의 현재 P(L)(없으면 unknown=0.30)에서 BKT로
  순서대로 갱신한 뒤 한 번만 저장(같은 문서 병렬 쓰기 레이스 방지).
- `feedback.js`의 render에서, 새 문제 채점 시(비-history, 로그인) saveSession과 함께 호출.
  usedHint는 세션의 hintUsed>0.
- 순수 로직(묶기 + BKT reduce) 단위 테스트 10개 통과: 태그 없는 문항 제외, 정답 상승/오답 하락,
  누적, 같은 오개념 묶음 = 순차 반영과 동일, 힌트 정답 상승폭 축소.

  시작한다(단계 5·8에서 연결).
- 아직 이 P(L)을 승급 판정이나 화면에 쓰진 않는다(단계 7·9). 데이터만 쌓임.

### 단계 5 — 진단된 오개념 풀 (2026-07)

  weak(0.15)에서 시작한다.

### 단계 6 — 순환 출제 (2026-07)

문제를 만들기 전에 "이번에 겨냥할 오개념"을 클라이언트가 골라 서버에 전달한다.

대상 선정 — `LearningService.pickTargetMisconceptions(uid, unit, level, count=2)`

| 단계 | 처리 |
|---|---|
| 후보 수집 | 소단원 오개념(misconceptions.subUnit) + 진단된 풀 |
| 레벨별 축소 | L1은 소단원 전체 / L2 이상은 진단된 풀 ∪ knowledgeState 기록 있는 것 (설계 4-4의 가+나) |
| 숙달 제외 | P(L) ≥ 0.90 제외 (`BKT.pickWeakest`) |
| 정렬·선택 | P(L) 오름차순 상위 2개 |
| 폴백 | 후보 없음·전부 숙달 → 빈 배열 반환 → 서버가 기존처럼 전체에서 자유 출제 |

기록이 없는 오개념은 unknown(0.30)으로 간주해 후보에 포함한다(사진에 안 걸린 오개념도 순환에 들어옴).

- 서버 `generateQuestions`: `targetMisconceptionIds` 인자 추가. 목록 밖 id는 버리고 최대 2개만
  사용, 해당 오개념을 프롬프트 목록 맨 앞으로 올린 뒤 "우선 겨냥" 지시문을 L1/L2A·L2B·L3
  세 프롬프트에 공통 삽입. 지정이 없으면 프롬프트는 기존과 동일(회귀 없음).
- 클라이언트 호출 지점 3곳(사진 분석 후 문제 풀기, 다음 문제 풀기, 마이페이지 이어서 풀기)은
  `pickTargetMisconceptionIds(unit, level)` 한 함수를 공유한다. 비로그인·조회 실패 시 빈 배열을
  반환해 문제 생성 자체는 막지 않는다.
- `MisconceptionDB`에 소단원 지도(`getSubUnitMap`) 추가. 개념 영역 지도와 오개념 87개 읽기를
  한 번의 캐시로 공유하도록 정리(추가 읽기 비용 없음).
- 이 단계까지는 "무엇을 출제할지"만 P(L)에 따라 바뀐다. 승급 판정은 아직 횟수 기반(단계 7).

### 단계 7 — 승급 판정 교체 (2026-07)

판정 규칙은 4-10 확정안을 그대로 구현했다.

- `feedback.js`: `calcPromotionTarget` 삭제. `_handleLevelProgress`가 `evaluatePromotion`을
  호출해 "대상 오개념 전부 P(L) ≥ 0.90"으로 승급을 판정한다. 합격 점수 조건은 승급에서 분리됐고
  (오답은 P(L) 하락으로 이미 반영), `PROMOTION_SCORE`는 "다시 풀어보기" 버튼 표시에만 남는다.
- 순서 보장: 이번 문제의 관측 저장(`applyBktObservations`)이 끝난 뒤 판정하도록 promise를
  `_bktApplied`에 보관하고 판정 직전 await한다. 안 그러면 갱신 전 값을 읽어 승급이 한 문제씩 밀린다.
- `firestore.js`: `_levelTargets`(레벨별 대상), `evaluatePromotion`(판정),
  `resetKnowledgeForLevel`(승급 시 초기값 복귀) 추가. 출제(`pickTargetMisconceptions`)와 승급이
  같은 대상 집합을 공유한다.
- 화면 표시: "누적 정답 n / 목표" → "Level n 진행도 %"(막대). 내부 계산은 대상 오개념 중 숙달
  비율이지만 개수는 노출하지 않는다. 소단원별 오개념 수가 1~22개로 크게 달라, 개수를 보여주면
  학습자가 학습이 아니라 숫자를 좇게 되고 단원 간 비교가 생긴다. 승급 배너 문구에서도 "오개념"을 뺐다.
  (한계: 오답으로 숙달이 풀리면 진행도가 내려간다. 거슬리면 평균 P(L) 기반 표시로 교체 가능.)
- 폴백: 대상이 0개인 소단원만 `incrementCorrectCount`(예전 방식) 사용. 화면에는 "누적 정답"으로 표시.
- 재도전 제외: "다시 풀어보기"(같은 문제 재풀이)는 정답을 이미 본 상태라 관측으로 세면 이해도가
  부풀려진다. 단계 4에서는 재도전도 관측에 포함됐는데, 승급이 이해도에 걸린 이 단계부터는
  실제 이해보다 빨리 승급하는 원인이 되므로 이해도 갱신 대상에서 제외했다.
- 시뮬레이션으로 소단원 크기별 예상 문항 수 확인(4-10 표). BKT 갱신 함수는 단계 0의 단위 테스트로 검증됨.

작업 중 발견한 데이터 결함: `misconceptions` 87개가 12개 소단원에만 분포하고, 열역학 법칙·특수
상대성 이론에는 오개념이 하나도 없었다(Firestore 실제 데이터로 확인). 단계 7-1에서 보강했다.

### 단계 7-1 — 오개념 데이터 보강 (2026-07)

기존 오개념은 FCI/FMCE(역학 전용)와 국내 논문에서 뽑았기 때문에, 표준 진단도구가 없는
열역학·특수 상대성 두 소단원이 비어 있었다. 각 영역의 표준 진단도구·오개념 연구를 근거로 채웠다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 개념 영역(dimension) | 17 | 19 (TH 열역학, SR 특수 상대성 추가) |
| 오개념 | 87 (12개 소단원) | 103 (14개 소단원 전체) |
| 판별 문장 | 166 | 214 |

- 열역학 8개(TH1~TH8): 열/내부 에너지 구분, 온도와 내부 에너지 동일시, 등온-단열 혼동, 단열 과정
  온도 방향, 제1법칙에서 일 누락, 등적 과정의 일, 열효율 100 %, 자발적 과정의 방향성.
- 특수 상대성 8개(SR1~SR8): 광속에 속도 합성, 동시성 절대화, 시간 지연을 착시로 봄, 고유 시간
  기준 혼동, 길이 수축 방향, 길이 수축을 압축으로 봄, 절대 운동 판별 가능, 질량 결손 부정.
- 근거 문헌은 아래 참고문헌의 열역학·특수 상대성 항목 8편. 모두 온라인 서지로 존재를 확인했다
  (Dimitriadi & Halkia의 권·호를 34(15) → 34(16)으로 정정).
- 오개념당 판별 문장 3개(틀린 문장 1~2 + 옳은 문장 1~2)를 붙여 문제 생성의 참고 자료로 쓰이게 했다.
- 사진 진단(`extractKeywords`) 정리: 비역학 단원에 오개념이 없던 시절의 임시 목록
  (M-W01/M-E01/M-T01, DB에 없는 가짜 id)을 제거하고, 오개념 목록에 소단원을 함께 실어
  "정한 소단원의 오개념 중에서만 고르라"로 지시를 바꿨다. 저장 단계
  (`addDiagnosedMisconceptions`)에서도 실제 존재하고 소단원이 일치하는 id만 남기도록 걸렀다.
  이 정리가 없으면 열역학·특수 상대성 사진이 가짜 id로 진단돼 L2/L3 범위 축소가 작동하지 않는다.
- (단계 7-2에서 해소됨) 당시 남은 결함: 기존 오개념 17개에 판별 문장이 없다(I2, I4, AF6, AF7, CI2, CI3, Ob, R3, G1, G2, ME3,
  ME6, ME7, WI3, WI4, WI5, MD1). 단계 8(사전 진단검사)이 문장을 표본으로 쓰므로 그전에 보강 필요.

### 단계 7-2 — 진단검사용 데이터 보강 (2026-07)

단계 8(사전 진단검사)은 소단원의 `misconception_sentences`에서 서로 다른 오개념 5개의 문장을
뽑아 쓴다. 착수 전 데이터를 점검해 두 가지 결함을 확인하고 보강했다.

| 결함 | 이전 | 이후 |

### 남은 구조적 한계 — 오개념이 없는 개념은 측정되지 않는다

출제 범위와 측정 범위가 다르다. 문제는 소단원명·기출 유형(`question_patterns` 116개)·오개념을
함께 넣어 만들기 때문에 오개념 목록에 없는 개념도 문항에 등장하고, L1의 5문장 중 태그가 붙지
않는 3~4문장이 실제로 그 역할을 한다. 그러나 이해도와 승급은 오개념 단위로만 계산되므로,
오개념으로 등록되지 않은 개념은 학습에는 등장해도 측정에는 반영되지 않는다.

해결 방향 세 가지 (Phase 3 이후 과제)

| 방향 | 내용 | 비용 |
|---|---|---|
| A. 지식 요소 확장 | `misconceptions`에 `kind`를 두어 "오개념"과 "개념 요소"(예: 충격량-운동량 정리 적용, F-t 그래프 면적 해석)를 함께 지식 요소로 다룸. BKT·태깅·승급 파이프라인을 그대로 재사용 | 낮음 |
| B. 유형 커버리지 축 | `question_patterns` 기준으로 "이 단원 유형 중 몇 개를 다뤘는지"를 측정과 별도로 표시 | 낮음 |
| C. 현행 유지 | 측정 단위를 오개념으로 한정하고 논문 한계로 명시 | 없음 |

A가 이론적으로도 표준에 가깝다. BKT의 지식 요소(KC)는 본래 기능·개념 단위이며, 오개념만을 KC로
쓴 것이 오히려 본 시스템의 특수한 선택이다. 개념 요소의 근거는 논문 인용이 아니라 교육과정
성취기준에서 가져올 수 있어 문헌 검증 부담도 없다.

### 단계 8-1 — 판별 문장 전수 검증 (2026-07)

배포 후 학생이 물리적으로 옳게 판단한 문장을 앱이 오답 처리한 사례가 발견됐다. AI가 생성한
문장의 `isWrong` 라벨이 틀렸는데 서버는 형식(문장 5개·불리언 여부·태그 유효성)만 검사하고
사실 여부는 검사하지 않았다. **정답이 무엇인지를 AI가 정하고 아무도 검사하지 않는 구조**다.

대책으로 Level 1 문장을 검증된 판별 문장 풀에서 가져오기로 하고, 그 전제로 343개를 전수 검토했다.
**15개에서 문제를 발견**했다.

| 급 | 내용 | 개수 |
|---|---|---|
| A | 라벨이 사실과 다름 (I1-S02, ME8-S01, WR2-S01, AT6-S01, WI1-S01) | 5 |
| B | 물리 명제가 아님 — 논문의 학생 응답 서술을 그대로 옮김 (ME9·ME10×2·ME13) | 4 |
| C | 조건 미지정으로 참·거짓이 갈림 (I3-S01/S02, ME12-S01, AT6-S02, MO1-S04, AF6-S01) | 6 |

- **ME8-S01** "물체가 2배 먼 거리를 이동했으므로 운동에너지도 2배이다" — 일정한 힘이면 W=Fd라 참.
- **WR2-S01** — 같은 오개념의 `correctConcept` 필드가 "맞으나"라고 스스로 참이라고 서술(자기모순).
- **AT6-S01** "전자가 원자핵에서 멀수록 에너지 준위가 높다" — 고교 보어 모형에서는 참.

### 단계 8-2 — 채점·관측 경로 결함 수정 (2026-07)

배포 후 한 세트(5문장)에서 **2개의 `isWrong` 라벨이 반대**로 나온 사례가 확인됐다. 학생이
물리적으로 옳게 판단했는데 하나는 "옳은 문장을 잘못 골랐다"로 −25점, 하나는 "틀린 문장을
못 찾았다"로 처리돼 35점이 나왔다. 조사 과정에서 결함 6개를 확인했다.

| # | 결함 | 위치 |
|---|---|---|
| 1 | `isWrong` 라벨이 사실과 반대 (근본 원인) | 문제 생성 |
| 2 | AI 해설이 자기 라벨과 정반대인데 대조하지 않음 | 채점 |
| 3 | 서술형 채점이 옳은 답을 오답 처리 | 채점 |
| 4 | 부제 "N개 중 M개 정답"이 미체크 문항을 정답으로 셈 | 채점 집계 |
| 5 | **미체크 문항이 AI의 임의 판단으로 BKT 관측에 들어감** | 이해도 갱신 |
| 6 | 4분류 이름이 오해를 부름 | 화면 |

**4분류 자체는 정상**이었다. 분기 조건(`isWrong` × 체크 여부)은 논리적으로 맞고, 문제는
그 입력값이 오염됐고 미답변 문항까지 집계에 섞인 것이었다.

**문항 검수 (결함 1·2 대책)** — 채점 호출의 응답에 `statementIsWrong`을 추가했다. 학생 답변과
무관하게 "이 문장 자체가 물리적으로 거짓인가"를 다시 판정하게 하고, 생성 단계의 `isWrong`과
어긋나면 그 문항을 **무효**로 만든다.

| 무효 문항 처리 | |
|---|---|
| 점수 | 가감 없음. 남은 문항 기준으로 100점 만점 환산 |
| 이해도 | 태그를 떼어 관측에서 제외 |
| 화면 | "검수 중인 문항" 그룹에 따로 표시 |
| 로그 | `isVoided: true`로 저장 — 문항 오류율 측정에 사용 |
| 서버 로그 | `console.warn`으로 단원·문장과 함께 기록 |

재판정 값이 없으면(구버전 응답) 검수를 건너뛴다. 없다는 이유로 무효로 만들지 않는다.

**`isCorrectAnswer` 확정 (결함 4·5 대책)** — 서버가 세 경우를 명시적으로 정한다.

| 상황 | `isCorrectAnswer` | BKT 관측 |
|---|---|---|
| 틀린 문장을 고르고 이유도 맞음 | true | 정답 |
| 틀린 문장을 골랐으나 이유 틀림 | false | 오답 |
| **틀린 문장을 못 찾음 (미체크)** | **false** | **오답** |
| 옳은 문장을 고름 (헛다리) | false | 태그 없음 |
| 옳은 문장을 안 고름 | true | 태그 없음 |

미체크를 관측에서 **제외하지 않고 오답으로 센다**. 못 찾은 것은 "그 오개념을 알아보지
못했다"는 진짜 증거이고, 제외하면 아무것도 체크하지 않을 때 이해도가 영원히 안 떨어지는
구멍이 생긴다. 예전 코드(`gradedItem?.isCorrectAnswer ?? !q.isWrong`)는 미체크 문항에 AI의
임의 판단을 넣어, **안 푼 문제로 이해도가 오르는** 상태였다.

**분류 이름 (결함 6)** — 이름을 풀어 쓰는 안을 검토했으나 기존 이름을 유지하기로 했다.
카드 안의 라벨만 "틀린 이유" → "이 문장이 틀린 이유"로 바꿔, 해설 본문과 어긋나 보이던 것을 없앴다.
분류 자체의 혼동은 새로 생긴 "검수 중인 문항" 그룹이 상당 부분 흡수한다(엉뚱하게 오답 처리되던
문항이 그쪽으로 빠지므로).

**검증** (5개 시나리오를 실제 분기 코드로 실행)

| 케이스 | 결과 |
|---|---|
| 이번 사고 재현 (라벨 2개 반대) | 35점 → **100점**, 무효 2건, BKT 관측은 정상 문항 1건만 |
| 정상 세트, 둘 다 정답 | 100점, 관측 2건 모두 정답 |
| 아무것도 안 고름 | 0점, **관측 2건 모두 오답** (예전엔 정답으로 올라갔음) |
| 5문장 전부 체크 (찍기) | 0점, 헛다리 4건 감점 |
| 재판정 없는 구버전 응답 | 무효 0건, 기존 동작 유지 |

**이해도 초기화** — 기존 `knowledgeState`는 오염된 관측으로 만들어졌다.
`functions/reset-knowledge.js`를 추가했다(기본은 미리보기, `--apply`로 실행). 이해도와
`diagnosticDone`만 지우고 세션 기록·레벨·진단 풀은 남긴다.

`users/{uid}` 문서 자체는 앱이 만들지 않는다(하위 컬렉션에만 쓴다). Firestore는 이런 경로를
"존재하지 않는 상위 문서"로 취급해 `collection('users').get()`에 넣어주지 않으므로,
관리자 SDK의 `listDocuments()`로 열거해야 한다.

### 단계 8-3 — 진행률 표시 수정 (2026-07)

특수 상대성 이론(오개념 8개)에서 **만점을 받아도 진행률이 0%에 머무는** 현상이 보고됐다.
확인된 상태는 SR1 0.622 / SR2 0.520 / SR3 0.526 / SR5 0.217 / SR7 0.520, 나머지는 기록 없음(0.30).
숙달(≥ 0.90)이 0개라 `mastered / total` = 0이었다.

원인은 계산 오류가 아니라 **지표의 해상도**다. 한 문제가 겨냥하는 오개념은 2개이고 숙달에는 같은
오개념에 정답 2번이 필요하므로, 오개념 N개짜리 소단원은 앞의 N/2문제 동안 숙달이 하나도 안 나온다.

| 문제(전부 100점) | 지금 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|---|
| 개수 기준 (기존) | 0% | 0% | 0% | 0% | 0% | 13% | 38% | 63% | 88% | 100% |
| 거리 기준 (수정) | 21% | 36% | 53% | 67% | 80% | 89% | 97% | 99% | 99% | 100% |

4-10의 진행률 식으로 교체했다(`LearningService._masteryRatio`). 승급 조건은 그대로다.

### 단계 8-4 — 틀린 문장 개수 강제 (2026-07)

Level 1에서 틀린 문장 1개를 요청했는데 3개가 생성됐다. 개수는 프롬프트 지시만 있고 서버 검사가
없었다(`questions.some(q => q.isWrong)` — 1개 이상이면 통과). 이 개수에 배점(100 ÷ 틀린 문장 수),
체감 난이도, 헛다리 감점폭이 걸려 있다. 서버에서 세어 다르면 재생성하고, 마지막 시도에서는
경고만 남기고 그대로 쓴다(생성 실패를 띄우는 쪽이 더 나쁘다).

### 단계 8-5 — 라벨 검증을 생성 단계로 이동 (2026-07)

단계 8-2의 문항 검수는 **채점할 때** 대조했다. 그래서 어긋난 문항을 학생이 이미 다 푼 뒤에야
발견했고, 결과 화면에 "채점에서 뺀 문항" 카드가 남았다. 학습자에게는 시스템 사정을 통보받는
화면이라 좋지 않다. 검사를 학생에게 보내기 전으로 옮겼다.

| | 단계 8-2 | 단계 8-5 |
|---|---|---|
| 검사 시점 | 채점 시 | 생성 시 (`verifyStatementLabels`) |
| 어긋나면 | 문항 무효 + 화면 표시 | 세트 폐기 후 재생성 |
| 학생이 보는 것 | 검수 카드 | 검증 통과 문장만 |

검증 호출의 설계 — 문장 텍스트만 준다. 오개념 목록·겨냥 지시·생성 라벨을 주면 앞의 판단을
따라가 검증이 성립하지 않는다. 표기 관례(부호, 벡터 화살표, 기호 이름)만 다른 경우는 참으로,
교과서에 따라 갈리는 문장은 `ambiguous`로 판정하게 하고 둘 다 폐기 사유로 쓴다.

3회 시도 후에도 불일치면 검증 쪽 라벨을 채택한다(단, 채택 후 틀린 문장이 0개가 되면 채택하지
않는다 — 채점이 성립하지 않는다). 판정만 하는 호출이 개수 맞추기·소재 다양화·오개념 겨냥을
겸하는 생성 호출보다 라벨에 관해서는 신뢰도가 높다는 판단이다.

채점 단계의 `statementIsWrong` 대조는 유지하되 **화면에 반영하지 않는다.** 세 번째 판정이
갈리면 이해도 관측에서만 제외하고 로그를 남긴다. 점수 한 문항의 오차보다 이해도 오염이
오래 남기 때문이다. 이 로그 건수 = 생성 검증을 통과하고도 남은 문항 오류율(논문 실측치).

비용 — 문제 생성마다 AI 호출 1회 증가.

### 단계 9 — 마이페이지 이해도 표시 (2026-07)

측정한 P(L)을 학습자가 볼 수 있는 유일한 자리다. 마이페이지 소단원 상세에 카드 하나를 넣는다.

```
이 소단원 이해도                    21%
▓▓▓▓░░░░░░░░░░░░░░░░
확인 끝난 개념 0 / 8

문제를 풀면 정답·오답에 따라 진행도가 오르내립니다.
100%가 되면 다음 레벨로 올라갑니다.
```

**오개념 하나하나의 값은 내보내지 않는다.** 처음에는 오개념별 막대 목록을 함께 그렸으나
걷어냈다. 학습자에게 필요한 건 "이 소단원이 얼마나 남았나"이고, 개별 목록은 문제 화면에서
감춘 것과 똑같은 부작용("몇 개짜리 단원인가"에 신경이 쏠림)을 마이페이지에 그대로 옮긴다.
`fetchUnitMastery`는 `{mastered, total, ratio}`만 반환한다.

같은 이유로 메인 통계의 "교정한 오개념 N/M"도 넣었다가 뺐다. 학습 횟수·평균 점수와 달리
학습자가 그 숫자로 할 수 있는 일이 없다.

**표시 값은 4-10의 진행률 식을 그대로 쓴다.** `BKT.progressRatio(pL)` 하나로 통일해
문제 화면(`_masteryRatio`)과 마이페이지가 같은 함수를 호출한다. 두 화면이 같은 상태를 다른
숫자로 말하면 "어느 쪽이 맞냐"만 남는다.

P(L)을 그대로 %로 쓰지 않는 이유 — 아직 아무 증거가 없는 오개념이 30%로 표시된다.
학습자는 이를 "30%는 안다"로 읽지만 실제 의미는 "사전확률 0.30"이다.

한 번도 측정 안 된 오개념도 분모에 넣는다. 측정된 것만 세면 "3개 중 3개 숙달"과
"8개 중 3개 숙달"이 구분되지 않는다.

**검증** (렌더 경로 실행, 375×812)

| 항목 | 결과 |
|---|---|
| 카드 내용 | 제목 없음 / 이해도 21% / 확인 끝난 개념 0 / 8 / 안내 문구 |
| 막대 폭 | 21% (값과 일치) |
| 남은 오개념별 행 | 0개 |
| 통계 카드 | 2개(총 학습 횟수·평균 점수), 2열 그리드 복귀 |
| 가로 스크롤 · 콘솔 에러 | 없음 |

### 단계 9-1 — 문항 신고 (2026-07)

문장의 참·거짓은 생성 단계에서 독립 호출로 검증한다(8-5). 그러나 **계산 문제, 해설,
서술형 채점은 여전히 AI가 혼자 판단**하고 아무도 대조하지 않는다. 그쪽이 틀렸을 때
학생이 말할 곳이 없다.

**위치** — 결과 화면의 각 문항 카드 하단. 문제를 푸는 중에는 학생이 답을 모르므로 신고할
근거가 없다. 채점 결과와 해설을 본 뒤라야 판단이 선다. 네 분류 카드에 모두 붙는다.

**사유** (`REPORT_REASONS`)

| code | 문구 | 잡으려는 것 |
|---|---|---|
| `label_should_be_correct` | 이 문장은 맞는 것 같아요 | 라벨 반대 |
| `label_should_be_wrong` | 이 문장은 틀린 것 같아요 | 라벨 반대 |
| `bad_explanation` | 해설이 이상해요 | 해설 오류 |
| `bad_grading` | 채점이 잘못됐어요 | 서술형 채점 |
| `unclear` | 문제가 이해가 안 돼요 | 문장 모호 |
| `etc` | 기타 (직접 입력) | 예상 밖 |

자유 입력만 받으면 아무도 안 쓰고, 고르기만 시키면 예상 밖의 오류를 못 듣는다. 고정 항목
다섯 개 뒤에 `기타`를 두고 그때만 서술 칸을 연다(빈 기타는 전송 불가).

**🔑 신고는 점수·이해도를 바꾸지 않는다.** 신고가 관측을 지우게 만들면 "틀릴 때마다 신고"가
최적 전략이 되어 이해도가 영원히 떨어지지 않는다. 학생에게는 "확인해볼게요"만 보여주고,
모아서 사람이 고친다.

**저장** — `question_reports` 컬렉션. 문장 원문·해설·라벨·학생 답변을 통째로 복사해 넣는다.
세션 참조만 남기면 문제를 고쳐 다시 시딩했을 때 원래 뭐가 문제였는지가 사라진다.

규칙은 **생성만 허용**한다(`request.resource.data.uid == request.auth.uid`). 읽기를 막는 이유는
신고에 그 사람이 쓴 답변이 들어가기 때문이고, 수정·삭제를 막는 이유는 논문 집계에 쓰기
때문이다. 검토는 `functions/list-reports.js`(관리자 SDK)로 한다.

**논문에서 쓸 지표**

| 지표 | 의미 |
|---|---|
| 신고율 | 학생이 체감한 문항 오류율 |
| 사유 분포 | 어느 경로가 약한가 (라벨 / 해설 / 서술형 채점) |
| 자동 검출과의 교집합 | 8-5 검증이 실제 오류를 얼마나 잡는가 |

마지막 항목이 핵심이다. 자동 검출(`라벨 대조 불일치`)에는 정답지가 없다. 학생 신고가 그
역할을 한다.

**검증** (렌더 경로 실행)

| 항목 | 결과 |
|---|---|
| 카드마다 버튼 | 2개 문항 → 2개 |
| 비로그인 | 버튼 0개 (저장할 uid가 없다) |
| 처음 상태 | 보내기 비활성 |
| 일반 사유 선택 | 입력칸 닫힘, 보내기 활성 |
| 기타 선택 | 입력칸 열림, 보내기 **비활성** |
| 기타 + 입력 | 보내기 활성 |
| 기타 + 공백만 | 보내기 비활성 |
| 375×812 / 903×694 | 제목·보내기 다 보임, 잘림 없음 |

원인 분석에서 하나 더 확인된 것: 오류가 난 문장이 `ε = -N(ΔΦ/Δt)` 였다. 교과서에 따라 크기만
`ε = N(ΔΦ/Δt)`로 쓰므로 참·거짓을 단정할 수 없다. 공식 판별 문장에서 부호 관례·벡터 표기·기호
이름·조건 없는 근사식으로 참거짓을 가르는 문장을 금지하고, 변수가 바뀌거나(`W = mv²`)
분자·분모가 뒤집힌(`a = m/F`) 형태만 쓰게 했다.
